## 为什么需要反思校验？


大模型本质上是概率生成引擎，输出可能存在以下问题：


- 事实错误（幻觉）


- 格式不符合要求


- 逻辑不自洽


- 遗漏用户的要求


反思校验系统就是Agent的"质检部门"，确保输出质量。


## 5.1 结果自检


在返回给用户之前，对输出进行多层校验：


### 5.1.1 事实真实性校验


- 关键事实声明是否可以通过知识库验证？


- 数字、日期、名称是否准确？


- 引用来源是否可靠？


- 是否使用了RAG溯源来支撑论断？


### 5.1.2 格式合规性校验


- JSON输出是否符合Schema？


- 代码是否能通过编译/运行？


- SQL语句语法是否正确？


- API调用的参数是否完整？


### 5.1.3 逻辑闭环校验


- 结论是否由前提合理推导出来？


- 是否存在前后矛盾？


- 是否回答了用户的所有问题？


- 推理链条是否完整？


## 5.2 执行复盘


每次任务执行后的经验沉淀，让Agent越来越聪明：


### 5.2.1 失败原因分类总结


- 工具调用失败 → 是权限问题还是参数错误？


- 规划不合理 → 是否低估了任务复杂度？


- 理解偏差 → 是否误解了用户意图？


- 知识不足 → 是否需要补充RAG知识？


### 5.2.2 Prompt迭代优化


- 记录哪些类型的任务容易出错


- 针对性优化对应的System Prompt


- 添加更多Few-shot示例


- 强化边界约束条件


### 5.2.3 错误规避策略沉淀


```
// 错误模式库示例
```

## 5.3 高阶互评


### 5.3.1 双Agent交叉校验


- Agent A 生成答案


- Agent B 作为"审核员"独立检查


- Agent B 发现问题 → 反馈给 Agent A 修改


- 两个Agent意见不一致 → 引入第三个仲裁


### 5.3.2 多轮自我修正重执行


1. 第一次执行 → 得到结果R1


2. 自我评估R1的质量 → 发现问题P


3. 针对问题P修正后重新执行 → 得到R2


4. 再次评估 → 如果仍有问题则继续


5. 达到质量阈值或最大轮次后停止


## 反思系统的实际价值


没有反思系统的Agent就像一个从不复盘的人——可能会反复犯同样的错误。有了反思系统：


- 同类错误的发生率持续下降


- 输出质量的稳定性显著提高


- 面对新场景的适应能力增强


- 用户的信任度逐步建立
