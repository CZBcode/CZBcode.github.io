## 什么是RAG？


RAG（Retrieval-Augmented Generation，检索增强生成）的核心思想很简单：


不把所有知识塞进模型里，而是在需要的时候去"查阅资料"，然后把查到的内容交给模型生成答案。


这解决了大模型的三个根本问题：知识过期、知识不可控、知识成本高。


## 5.1 文档预处理


RAG的第一步是把各种格式的文档变成模型可以理解的文本。


### 5.1.1 文档解析


| 推荐工具 | 注意事项 |  |
| --- | --- | --- |
| PyPDF2, pdfplumber, Unstructured | 扫描件需要OCR |  |
| 直接读取 | 保留标题层级结构 |  |
| python-docx | 注意样式和表格 |  |
| BeautifulSoup, trafilatura | 去除导航和广告 |  |
| Unstructured, Notion API | 保留块结构 |  |


### 5.1.2 智能分块策略


分块质量直接决定RAG的效果。常用策略：


- **固定长度分割**：按字符数/Token数切分，简单但可能切断语义


- **递归字符分割**：按段落→句子→单词递归切分，保留层次结构


- **语义分块**：用embedding模型判断语义边界再切分，效果最好


- **重叠窗口**：相邻chunk之间保留重叠部分，避免信息丢失


```
# 推荐的分块配置

chunk_config = {

    "chunk_size": 500,       // 每块约500字符

    "chunk_overlap": 50,     // 重叠50字符

    "separators": ["\n\n", "\n", "。", " ", ""]

    // 优先在段落、句子处切分

}
```


## 5.2 双路召回


单一检索方式各有缺陷，双路召回结合两者优势：


### 5.2.1 BM25稀疏检索


- 基于关键词匹配的传统检索算法


- 优点：精确匹配能力强，对专有名词效果好


- 缺点：无法理解同义词和语义


- 工具：Elasticsearch、BM25Okapi、Rank-BM25


### 5.2.2 向量稠密检索


- 将query和文档都转为向量，计算余弦相似度


- 优点：能理解语义和同义词


- 缺点：对精确关键词匹配不如BM25


- 工具：FAISS、Chroma、Milvus


### 5.2.3 混合召回融合


结合两种检索结果，常用的融合算法：


- **RRF（Reciprocal Rank Fusion）**：按排名倒数求和，简单有效


- **加权评分**：给两个分数加权和


- **RRF + Rerank**：先用RRF粗排，再用交叉编码器精排


## 5.3 后置优化


### 5.3.1 Rerank重排序


对初步召回的结果重新打分排序：


- **交叉编码器（Cross-Encoder）**：同时输入query和document，精度更高但速度较慢


- **推荐模型**：bge-reranker、Cohere Rerank、jina-reranker


- 通常只对Top-K（如Top-20）做Rerank，平衡效果和速度


### 5.3.2 上下文压缩


召回的文档可能很长，需要压缩后再放入上下文窗口：


- 只保留与问题最相关的段落


- 去除冗余和重复内容


- 用LLM提炼关键信息


### 5.3.3 答案溯源


在答案中标注信息来源，一举三得：


- **防幻觉**：强制模型基于给定内容回答


- **可信度**：用户可以点击查看原文


- **可追溯**：出问题时可以定位到具体文档


## RAG效果评估指标


| 含义 | 目标值 |  |
| --- | --- | --- |
| 前K个结果中有多少是相关的 | > 0.8 |  |
| 相关结果中有多少被召回了 | > 0.9 |  |
| 第一个相关结果的排名倒数 | > 0.7 |  |
| 答案是否基于检索内容 | > 0.95 |  |
