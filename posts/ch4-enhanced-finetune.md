## 什么时候需要微调？


并非所有场景都需要微调。以下情况考虑微调：


- 通用模型在你的领域表现差（专业术语、行业知识）


- 需要特定的输出格式（特殊的JSON schema）


- 需要降低延迟或减小模型体积


- 数据隐私要求不能使用云端API


如果只是偶尔用用，Prompt工程 + RAG 可能就够了。


## 6.1 微调范式


### 6.1.1 SFT（Supervised Fine-Tuning，监督微调）


最基础的微调方式：用（输入，期望输出）对训练模型。


- **数据格式**：(instruction, input, output) 三元组


- **数据量**：通常需要几百到几万条高质量样本


- **效果**：让模型学会特定领域的知识和风格


### 6.1.2 LoRA（Low-Rank Adaptation，低秩适配）


不需要训练全部参数，只训练少量的适配器矩阵：


- **原理**：冻结原模型权重，在每层旁路加入低秩矩阵


- **优势**：训练参数量仅为原来的1%~5%，显存需求大幅降低


- **效果**：在全量微调的95%+效果上，成本仅为其几分之一


- **热门工具**：PEFT (Hugging Face)、Axolotl、LLaMA-Factory


### 6.1.3 DPO（Direct Preference Optimization，直接偏好优化）


不需要奖励模型，直接用偏好数据优化：


- **数据格式**：(prompt, chosen, rejected) 三元组


- **原理**：直接最大化好回答相对于坏回答的对数概率比


- **优势**：比RLHF简单很多，不需要训练奖励模型


- **适用场景**：让模型的输出风格更符合人类偏好


## 6.2 数据集构建


微调的数据质量远比数量重要。Agent相关的数据集类型：


### 6.2.1 Agent调用轨迹数据


- 记录真实的Agent运行过程（思考→行动→观察→结果）


- 包含成功案例和失败案例


- 可以从现有Agent系统中自动采集


### 6.2.2 规划推理样本


- (复杂任务, 分步规划过程, 最终答案)


- 重点展示如何拆解问题和选择路径


### 6.2.3 工具调用正确样本


- (用户请求, 正确的工具选择, 正确的参数, 执行结果)


- 每种工具至少几十个正例


## 6.3 推理部署优化


### 6.3.1 模型量化


降低模型精度以减小体积和加速推理：


| 位数 | 大小缩减 | 精度损失 |  |
| --- | --- | --- | --- |
| 16位 | ~50% | 几乎无 |  |
| 8位 | ~75% | 轻微 |  |
| 4位 | ~87.5% | 可接受 |  |


- **GGUF**：llama.cpp格式，适合CPU/消费级GPU推理


- **AWQ**：Activation-aware Weight Quantization，精度更好


- **GPTQ**：老牌量化方案，生态成熟


### 6.3.2 私有化部署


- **vLLM**：高性能推理服务，支持PagedAttention和连续批处理


- **Ollama**：本地模型运行最简单的方案，一行命令启动


- **LLaMA.CPP**：纯C++实现，可在普通电脑上跑大模型


- **SGLang**：结构化输出加速，适合Agent场景
