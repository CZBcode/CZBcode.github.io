## Agent生产的四大痛点


在实际落地Agent的过程中，几乎每个团队都会遇到以下四个核心痛点。了解它们的根因和解决方案，能帮你少走很多弯路。


## 痛点一：模型幻觉


### 表现


- 编造不存在的数据、事件、术语


- 自信地给出错误答案


- 引用不存在的来源


### 根因


大模型是基于概率生成文本的，而非基于事实数据库。它在"看起来合理"和"实际上正确"之间，倾向于前者。


### 解决方案


1. **RAG溯源**：强制模型基于检索到的文档回答，并在答案中标注来源


2. **事实校验**：用反思系统对关键事实进行二次验证


3. **多轮复核**：重要输出经过多个Agent交叉验证


4. **强约束Prompt**：明确告知"不知道就说不知道，禁止编造"


## 痛点二：上下文超限


### 表现


- 长对话中模型"忘记"了早期的内容


- 大文档无法一次性放入上下文


- 多轮任务执行后窗口耗尽


### 根因


模型的上下文窗口有限（即使是128K也不是无限的），且计算成本随长度平方增长。


### 解决方案


1. **记忆分层**：短时记忆（窗口内）+ 长时记忆（向量库）+ 实体记忆（结构化）


2. **摘要压缩**：用LLM将早期对话压缩为一句话摘要


3. **滚动窗口**：保留最新的N轮对话，淘汰最早的


4. **RAG外挂知识库**：长文档不放入窗口，需要时按需检索


## 痛点三：工具误调用 / 错参数


### 表现


- 调用不存在的工具


- 参数类型错误（字符串传了数字）


- 缺少必需参数


- JSON格式不合法


### 根因


模型生成工具调用指令时是基于"猜测"的，尤其是对于复杂或不常用的工具Schema。


### 解决方案


1. **强JSON Schema约束**：详细的字段描述、枚举值、示例


2. **前置校验**：调用前验证参数合法性，不合格则要求重试


3. **拦截重试**：格式错误时自动提示模型重新生成


4. **Few-shot示例**：提供正确的工具调用示例供模型模仿


## 痛点四：执行不稳定、随机性强


### 表现


- 同样的输入，不同次的输出差异很大


- 有时完美执行，有时完全跑偏


- 难以复现和调试问题


### 根因


采样策略中的随机性（Temperature > 0）加上复杂推理路径的组合爆炸。


### 解决方案


1. **步骤快照**：每一步执行后保存状态，支持回滚


2. **失败重试**：对不稳定步骤增加重试次数


3. **降级兜底**：多次失败后切换到更简单但更可靠的方案


4. **降低Temperature**：工具调用场景用 T=0.1~0.3


5. **确定性输出**：关键步骤使用 seed 参数保证可复现


## 痛点汇总表


| 严重程度 | 首要方案 | 辅助方案 |  |
| --- | --- | --- | --- |
| 🔴 高 | RAG溯源 | 反思校验 + 强约束 |  |
| 🔴 高 | 记忆分层 | 摘要压缩 + RAG |  |
| 🟠 中 | Schema约束 | 前置校验 + Few-shot |  |
| 🟠 中 | 步骤快照+重试 | 降级兜底 + 低Temperature |  |


## 应对心态


这些痛点不可能100%消除，但可以通过系统工程的方法将影响降到最低。关键是：


- **接受不完美**：Agent不是万能的，设计好降级路径


- **度量优先**：建立量化指标，客观评估改进效果


- **持续迭代**：根据实际反馈不断优化


- **人机协同**：在关键环节保留人工确认
